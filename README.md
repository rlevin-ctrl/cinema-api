# Cinema API (NestJS)

REST API кінотеатру: фільми, зали, сеанси та бронювання місць.
Домашнє завдання №1 курсу «Back-end розробка з Node.js (NestJS)».

## Технології

- **NestJS 12** (TypeScript)
- **class-validator / class-transformer** — валідація DTO
- **Swagger** — документація на `/docs`
- Дані зберігаються **в пам'яті** (без БД), щоб сфокусуватись на архітектурі та маршрутах

## Структура проєкту

```
src/
├── films/        # фільми: контролер, сервіс, DTO
├── halls/        # зали: контролер, сервіс, DTO
├── showings/     # сеанси: контролер, сервіс, DTO
├── bookings/     # бронювання: контролер, сервіс, DTO
├── data/         # сховище в пам'яті (DataService)
├── common/       # спільні типи
├── app.module.ts
└── main.ts
```

Кожен домен — окремий модуль. Контролери відповідають лише за HTTP-шар,
бізнес-логіка живе у сервісах. `ShowingsModule` імпортує `FilmsModule` та `HallsModule`
і використовує їхні **експортовані сервіси**; `BookingsModule` так само спирається
на `ShowingsService` і `HallsService`.

## Встановлення залежностей

```bash
npm install
```

## Запуск у режимі розробки

```bash
npm run start:dev
```

Сервер піднімається на `http://localhost:3000` (порт змінюється змінною `PORT`).

Збірка та запуск продакшн-версії:

```bash
npm run build
npm run start:prod
```

## Змінні оточення

Файл `.env` у корені проєкту (у репозиторій не потрапляє):

```env
PORT=3000
```

Приклад лежить у `.env.example`.

## Swagger

Після запуску документація доступна за адресою:

```
http://localhost:3000/docs
```

Усі DTO анотовані (`@ApiProperty`), для кожного маршруту вказані коди відповідей.

## Перевірка маршрутів

У корені лежить `requests.http` — файл для REST Client (VS Code / WebStorm / Rider).
Запити виконуються **згори вниз**: спочатку створюються фільм, зал, сеанс і бронювання,
далі йдуть запити на кожну помилку з опису маршрутів. Ідентифікатори підставляються
зі змінних (`{{createFilm.response.body.id}}`), вручну нічого вписувати не потрібно.

## Маршрути

**Фільми**

- `POST /films` — створити фільм
- `GET /films` — усі фільми
- `GET /films/:id` — один фільм
- `PATCH /films/:id` — оновити фільм
- `DELETE /films/:id` — видалити фільм (409, якщо є сеанси)

**Зали**

- `POST /halls` — створити зал (409, якщо назва вже зайнята)
- `GET /halls` — усі зали
- `GET /halls/:id` — зал разом з масивом `seats`
- `DELETE /halls/:id` — видалити зал (409, якщо є сеанси)

**Сеанси**

- `POST /showings` — створити сеанс
- `GET /showings?filmId=&date=` — сеанси з фільтрацією та сортуванням за часом
- `GET /showings/:id` — один сеанс
- `GET /showings/:id/seats` — місця залу з ознакою `isBooked`

**Бронювання**

- `GET /bookings` — усі бронювання
- `POST /showings/:id/bookings` — забронювати місця (409, якщо місце зайняте)
- `GET /showings/:id/bookings` — бронювання сеансу
- `DELETE /bookings/:id` — скасувати бронювання (місця звільняються)

## Особливості реалізації

- Ціна зберігається цілим числом у копійках (`12500` = 125 грн); підсумкова ціна
  бронювання = ціна квитка × кількість місць.
- Бронювання атомарне: якщо хоча б одне місце зі списку вже зайняте, повертається
  `409` і **жодне** місце не бронюється.
- Місця залу обчислюються з `rows` × `seatsPerRow`; окремої сутності місця немає,
  місце визначає пара `row` + `seat`.
- Сеанс не можна створити з датою в минулому або з некоректним ISO 8601.
